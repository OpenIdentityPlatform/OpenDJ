== Access Directory Entries Over REST

Use a fresh ZIP installation on an isolated test host with ports 1389, 4444, and 8443 available. Copy link:../attachments/Example.ldif[Example.ldif] into the `opendj` directory. Read the license before using `--acceptLicense`, then run the commands from that directory. See xref:../install-guide/chap-install.adoc#command-line-install[command-line installation] for setup options.

[source,bash]
----
./setup --cli --no-prompt --acceptLicense --hostname localhost \
  --ldapPort 1389 --adminConnectorPort 4444 \
  --enableStartTLS --generateSelfSignedCertificate \
  --rootUserDN 'cn=Directory Manager' --rootUserPassword password \
  --baseDN dc=example,dc=com --ldifFile Example.ldif
----

=== Enable the Handler

Bind HTTPS to loopback and reuse the JKS certificate generated during setup. Password-reset actions require a secure connection, even on loopback. See xref:../admin-guide/chap-connection-handlers.adoc#setup-http-connection-handler[Setting Up an HTTP Connection Handler] for other certificate configurations. `--trustAll` below is for the local server's self-signed administration certificate.

[source,bash]
----
bin/dsconfig set-connection-handler-prop \
  --hostname localhost --port 4444 \
  --bindDN 'cn=Directory Manager' --bindPassword password \
  --handler-name 'HTTP Connection Handler' \
  --set listen-address:127.0.0.1 --set listen-port:8443 \
  --set use-ssl:true --set key-manager-provider:JKS --set enabled:true \
  --trustAll --no-prompt

bin/stop-ds --restart

bin/dsconfig list-http-authorization-mechanisms \
  --hostname localhost --port 4444 \
  --bindDN 'cn=Directory Manager' --bindPassword password --trustAll --no-prompt

bin/dsconfig list-http-endpoints \
  --hostname localhost --port 4444 \
  --bindDN 'cn=Directory Manager' --bindPassword password --trustAll --no-prompt
----

Restarting applies the listener and TLS settings. The default `/api` endpoint is enabled and uses `HTTP Basic`. The exact-match identity mapper resolves a username to its `uid` entry.

=== Read a User

Export the locally generated certificate so `curl` can verify it:

[source,bash]
----
keytool -exportcert -rfc -alias server-cert -keystore config/keystore \
  -storepass:file config/keystore.pin -file server-cert.pem
----

[source,bash]
----
api=https://localhost:8443/api
curl --fail-with-body --cacert server-cert.pem --user 'bjensen:hifalutin' \
  "$api/users/bjensen?_prettyPrint=true"
----

The JSON response identifies `bjensen` and includes her mapped name and contact information. The mapping in `config/rest2ldap/endpoints/api/example-v1.json` uses `ou=people,dc=example,dc=com` as its user base.

=== Create, Update, and Delete a User

The sample account `kvaughan` belongs to the Directory Administrators group. Use it to create a temporary user named `rest-example` and read the new entry. The create request returns HTTP 201.

[source,bash]
----
curl --fail-with-body --cacert server-cert.pem --user 'kvaughan:bribery' \
  --header 'Content-Type: application/json' \
  --data '{"_id":"rest-example","_schema":"frapi:opendj:rest2ldap:user:1.0",
           "name":{"givenName":"REST","familyName":"Example"},"displayName":["REST Example"]}' \
  "$api/users?_action=create&_prettyPrint=true"

curl --fail-with-body --cacert server-cert.pem --user 'kvaughan:bribery' \
  "$api/users/rest-example?_prettyPrint=true"
----

Replace the writable fields with `PUT`. `If-Match: *` allows any current revision of the existing resource. To require a specific revision, use the `_rev` value returned by `GET`. Check that the response shows the new display name, then delete the test user.

[source,bash]
----
curl --fail-with-body --cacert server-cert.pem --user 'kvaughan:bribery' \
  --request PUT --header 'If-Match: *' --header 'Content-Type: application/json' \
  --data '{"name":{"givenName":"REST","familyName":"Example"},
           "displayName":["Updated REST Example"]}' \
  "$api/users/rest-example?_prettyPrint=true"

curl --fail-with-body --cacert server-cert.pem --user 'kvaughan:bribery' \
  --request DELETE "$api/users/rest-example?_prettyPrint=true"
----

`DELETE` returns the removed resource. A subsequent `GET` for `rest-example` returns HTTP 404.

=== Enable Access Logging

To enable HTTP access logging:

[source,bash]
----
bin/dsconfig set-log-publisher-prop \
  --hostname localhost --port 4444 \
  --bindDN 'cn=Directory Manager' --bindPassword password \
  --publisher-name 'File-Based HTTP Access Logger' --set enabled:true \
  --trustAll --no-prompt
----

See xref:../server-dev-guide/chap-rest-operations.adoc[Performing RESTful Operations] for more examples. HTTP requests use the authenticated account's LDAP privileges and access rights. See xref:../admin-guide/chap-privileges-acis.adoc[Configuring Privileges and Access Control] or continue with xref:./delegate-password-reset.adoc[Delegate Password Reset Permissions].
