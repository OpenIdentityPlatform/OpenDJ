[#how-to-kubernetes]
== Run OpenDJ in Kubernetes

Run a two-replica OpenDJ directory with the official Helm chart. The cluster needs Helm, `kubectl`, and a StorageClass that can provision one volume per server. Set `OPENDJ_VERSION` to a version that publishes the chart, and create `root-password.txt` with a non-empty password with no line terminator. See xref:../install-guide/chap-install.adoc#install-helm[Installing OpenDJ with Helm] for the available registries and OpenShift settings.

[source,bash]
----
CHART=oci://ghcr.io/openidentityplatform/charts/opendj-helm
kubectl create namespace directory
kubectl -n directory create secret generic directory-root --from-file=password=root-password.txt
----

Save `directory-values.yaml` with the following settings.

[source,yaml]
----
auth:
  existingSecret: directory-root
image:
  repository: ghcr.io/openidentityplatform/opendj/opendj
replication:
  enabled: true
replicaCount: 2
----

[source,bash]
----
helm install directory "$CHART" --version "$OPENDJ_VERSION" --namespace directory \
  -f directory-values.yaml --wait --timeout 15m
helm test directory --namespace directory
kubectl -n directory get pods,pvc
----

=== Verify writes on both replicas

Open two port forwards in separate terminals.

[source,bash]
----
kubectl -n directory port-forward pod/opendj-directory-0 11389:1389
kubectl -n directory port-forward pod/opendj-directory-1 21389:1389
----

Use the tools from the OpenDJ LDAP toolkit. Write an entry through port 11389, then look for it through port 21389. The update is asynchronous, so repeat the search until the entry arrives.

[source,bash]
----
ldapmodify --hostname localhost --port 11389 --bindDN 'cn=Directory Manager' \
  --bindPasswordFile root-password.txt <<'LDIF'
dn: ou=kubernetes,dc=example,dc=com
changetype: add
objectClass: top
objectClass: organizationalUnit
ou: kubernetes

LDIF
ldapsearch --hostname localhost --port 21389 --bindDN 'cn=Directory Manager' \
  --bindPasswordFile root-password.txt --baseDN ou=kubernetes,dc=example,dc=com \
  --searchScope base '(objectClass=*)' dn
----

=== Add and remove a replica

Keep the same chart version and values file. First add the planned peer to the list, then start its pod. If that pod will reuse a retained PVC, follow the xref:../admin-guide/chap-replication.adoc#helm-replica-resize[client traffic procedure] before starting it.

[source,bash]
----
helm upgrade directory "$CHART" --version "$OPENDJ_VERSION" -n directory \
  -f directory-values.yaml --set replicaCount=2,replication.peerCount=3 --wait --timeout 15m
kubectl -n directory rollout status statefulset/opendj-directory --timeout=15m
helm upgrade directory "$CHART" --version "$OPENDJ_VERSION" -n directory \
  -f directory-values.yaml --set replicaCount=3 --set-json replication.peerCount=null --wait --timeout 15m
kubectl -n directory rollout status statefulset/opendj-directory --timeout=15m
----

Forward the LDAP port of `opendj-directory-2` and verify that it has the earlier entry. Add a second entry there and confirm that it reaches the two original replicas. Stop writes to the third replica, wait for its last updates to reach the other servers, then reduce the StatefulSet before shortening the peer list.

[source,bash]
----
helm upgrade directory "$CHART" --version "$OPENDJ_VERSION" -n directory \
  -f directory-values.yaml --set replicaCount=2,replication.peerCount=3 --wait --timeout 15m
kubectl -n directory wait --for=delete pod/opendj-directory-2 --timeout=15m
helm upgrade directory "$CHART" --version "$OPENDJ_VERSION" -n directory \
  -f directory-values.yaml --set replicaCount=2 --set-json replication.peerCount=null --wait --timeout 15m
kubectl -n directory rollout status statefulset/opendj-directory --timeout=15m
helm test directory --namespace directory
----

Confirm that the two running replicas still hold both entries, and that `data-opendj-directory-2` is still present. For membership verification and how to return a retained replica, see xref:../admin-guide/chap-replication.adoc#helm-replica-resize[Resizing an OpenDJ Helm Release].
